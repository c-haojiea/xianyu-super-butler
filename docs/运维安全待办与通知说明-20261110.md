# 一、安全风险与缺陷清单

## 0. 紧急度判定

**当前没有必须立刻处理的高危漏洞。** 判定依据：

| 风险 | 为什么不算紧急 |
|---|---|
| 8081 局域网暴露 | 后台有图形验证码防爆破，管理员密码已确认非默认值，同网段攻击者还需要知道地址 |
| 日志含买家手机号/地址 | 不外泄就没事，风险只在「分享日志」这个动作上 |
| 数据库 ACL 宽松 | 只有本机存在其他登录用户时才被利用；家用单用户笔记本影响很小 |

**升级为「必须立刻处理」的触发条件**（任一命中就先停下做修复）：

- 发现同网段/校园网内有陌生设备访问过后台（日志里出现非本机 IP 的登录记录）
- 需要把日志、数据库、备份发给任何人（含发给我排查）
- 这台电脑被多人共用，或借给他人使用
- 后台管理员密码被改回简单密码，或关闭了图形验证码

## 1. 风险清单

### P0-1 后台 8081 监听所有网卡，且为明文 HTTP

- **证据**：`global_config.yml` → `AUTO_REPLY.api.host: 0.0.0.0`；实测本机 4 个网卡地址均返回 200
  ```
  LAN 192.168.128.1 -> 200
  LAN 192.168.88.1  -> 200
  LAN 192.168.238.1 -> 200
  LAN 10.40.1.220   -> 200
  ```
- **影响**：同 WiFi / 同网段任何设备可打开后台登录页；密码走 HTTP 明文，可被抓包；`10.40.1.220` 形似校园网，同网段可能有陌生人。
- **修复**：`host: 127.0.0.1`，重启管家。代价：手机、其他电脑不能再访问后台。
- **副作用**：若将来要从手机看后台，需要改回并接受风险，或改为反向代理 + HTTPS。

### P0-2 买家手机号与完整收货地址明文写入日志

- **证据**：单日日志实测 `59` 行 `📱 手机号: 1xxxxxxxxxx`、`40` 行 `📍 收货地址: 省市区街道…`；`logs` 共 82.4 MB / 11 个文件，保留 7 天。
- **来源代码**：`XianyuAutoAsync.py` 的 `fetch_order_detail_info`（手机号、收货地址两行 `logger.info`）。
- **影响**：属于个人信息（PII）泄露面。一旦日志被分享、上传、打包发出，买家隐私即外泄。
- **修复**：日志脱敏——手机号保留前 3 后 4（`183****7043`），地址只保留到市级。数据库里保留完整值（发货需要）。
- **注意**：历史日志（已生成的 82 MB）不会被自动脱敏，需要单独清理一次。

### P0-3 数据库及 8 个备份明文存放账号凭证，文件权限过宽

- **证据**：
  - `cookies.value` 存的是**完整登录 Cookie**，等于账号凭证
  - `data\` 下有 `xianyu_data.db` + **8 个** `xianyu_data_backup_*.db`，每个约 0.8 MB
  - ACL：`BUILTIN\Users` 可读、`NT AUTHORITY\Authenticated Users` 可修改
- **影响**：本机任何登录用户复制 db 文件即可接管店铺账号；备份越多，泄露面越大。
- **修复**：
  1. 备份只保留最近 3 天（或 3 份），其余删除
  2. 收紧 `data\` 目录 ACL 为仅当前用户
  3. 长期方案：备份加密，或存到只有当前用户可读的目录

## 1. 会发哪些消息（共 4 类）

| # | 类型 | 触发条件 | 标题 |

# 三、开机自动启动机制

## 1. 现状（实测）

| 项 | 值 |
|---|---|
| 任务名 | `XianyuSuperButler` |
| 触发器类型 | **登录时**（LogonTrigger），不是开机时 |
| 延迟 | `PT10M` = **登录后 10 分钟** |
| 动作 | `wscript.exe "静默启动.vbs"` |
| 工作目录 | 项目根目录 |
| 防重复 | `IgnoreNew`（已在运行就不再启动） |
| 超时 | `PT0S`（不限） |
| 运行身份 | `LAPTOP-U62VNGR7\Lenovo` |

为什么用「登录后」而不是「开机后」：滑块验证需要桌面浏览器会话就绪，开机时用户还没登录，自动化会失败。

配套还有第二个任务：

| 任务名 | 触发器 | 动作 |
|---|---|---|
| `XianyuPendingRescue` | 每 5 分钟重复 | `wscript.exe "巡检.vbs"` |

## 2. 修改延迟的方法

### 方法 A：图形界面（最直观）

1. `Win + R` → 输入 `taskschd.msc` → 回车
2. 左侧「任务计划程序库」→ 找到 `XianyuSuperButler`
3. 双击 → 切到「触发器」标签 → 选中那条触发器 → 「编辑」
4. 勾选「延迟任务时间」，改成想要的时长 → 确定

### 方法 B：PowerShell 一行改（推荐，可复制）

```powershell
$t = Get-ScheduledTask -TaskName 'XianyuSuperButler'
$t.Triggers[0].Delay = 'PT5M'
Set-ScheduledTask -TaskName 'XianyuSuperButler' -Trigger $t.Triggers
```

把 `PT5M` 换成想要的时长：

| 想要的延迟 | 写法 |
|---|---|
| 立即启动 | `PT0M` |
| 3 分钟 | `PT3M` |
| 5 分钟 | `PT5M` |
| 10 分钟（当前） | `PT10M` |
| 20 分钟 | `PT20M` |
| 30 分钟 | `PT30M` |
| 1 小时 | `PT1H` |

验证是否改成功：

```powershell
(Get-ScheduledTask -TaskName 'XianyuSuperButler').Triggers[0].Delay
```

### 方法 C：命令行（备选）

```cmd
schtasks /Change /TN "XianyuSuperButler" /DELAY 0005:00
```

`/DELAY` 格式是 `分钟:秒`，`0005:00` 表示 5 分钟。

## 3. 注意事项

- 改完**不需要重启电脑**，下次登录时生效；想立刻验证就手动触发：
  ```powershell
  Start-ScheduledTask -TaskName 'XianyuSuperButler'
  ```
- 如果管家已在运行，`IgnoreNew` 会让这次触发直接跳过，属正常。
- 延迟调太短（如 `PT0M`）的风险：桌面还没加载完就去跑浏览器的滑块验证，失败率会升高。建议 **不短于 3 分钟**。
- 想临时停用自启：
  ```powershell
  Disable-ScheduledTask -TaskName 'XianyuSuperButler'
  Enable-ScheduledTask  -TaskName 'XianyuSuperButler'
  ```
